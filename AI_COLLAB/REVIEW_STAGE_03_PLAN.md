## 二、必须改（3 项）

### M1 — HC-12 是半双工，遥测 20~50 Hz 持续发会与指令碰撞

**查证**（HC-12 官方手册 v2.3B）：模块成对使用时**只能半双工，不能空中同时收发**。

**问题**：规划同时要求「遥测 20~50 Hz 持续回传」和「电脑随时下发 CMD_VEL/CMD_STOP」—— 在半双工链路上这两者会互相碰撞丢包。与阶段 2 踩过的「OLED 刷新阻塞 I2C 总线」是同类时序冲突。

**要求 Codex 明确**：

1. 定**主从轮询**时序：例如电脑发一帧指令 → STM32 回一帧遥测（请求-应答），或 STM32 固定 50 ms 发一次遥测但电脑下发前先申请窗口；
2. **遥测频率现实值定 20 Hz**（50 Hz 对半双工 HC-12 偏乐观，不建议写进验收硬指标）；
3. 帧要短（TELEMETRY 只传必要字段，定点数不用浮点字符串）；
4. 在 S3-01 接口单里就写清半双工时序，不许实现模型自己定。

### M2 — 波特率方向与距离目标搞反；SET 引脚流程要补

**查证**（手册 FU3 默认全速模式的串口↔空中波特率对应）：

```text
串口 115200 → 空中 236000 bps → 灵敏度 −100 dBm → 通信距离最短
串口 9600   → 空中 58000 bps  → 灵敏度 −107 dBm（出厂默认）
串口 2400   → 空中 15000 bps  → 灵敏度 −112 dBm
串口 1200   → 空中 5000 bps   → 灵敏度 −117 dBm → 距离最远（~1000 m）
```

**问题**：规划写「115200，距离远/干扰大可降为 9600 或 19200」—— 把因果关系说反了。HC-12 的**低波特率才换来远距**，115200 是牺牲距离换速率。

**要求 Codex 明确**：

1. **默认定 9600 8N1**（出厂默认、最稳、室内距离足够），不要上来 115200；如确实要高频遥测再评估，但要写明"牺牲距离"的代价；
2. 补 **SET 引脚流程**：正常工作时释放（高电平/悬空），**配频道/波特率时拉低进 AT 模式**；
3. 补一次性配置步骤：两块 HC-12 用 USB-TTL 分别设成**同频道（如 CH001）、同波特率**，参数掉电保存；
4. 补供电注意：HC-12 发射峰值 ~100 mA，**不要从 STM32 的 3.3V 取电**，单独 5V/3.3V 供电并共地；TX/RX 电平匹配（VCC 5V 时 TX 是 5V 电平，注意 STM32 引脚兼容性，建议 HC-12 也用 3.3V 供电）。

### M3 — 启用 USART1 又是架构变更（CubeMX），规划完全没提

**查证**（本工程 20:27）：

```text
breathing.ioc 中无任何 USART 配置；PA9/PA10 空闲
main.h 第 82 行 M1zuoqian_Pin = GPIO_PIN_9 但端口是 GPIOE（PE9），不冲突 ✅
```

**问题**：PA9/PA10 可用是好消息，但启用 USART1 必须改 `.ioc` 重生成 —— **会再次冲掉 Keil 里手动 Add 的 7 个 .c**（pid/control/encoder/motor/oled/chassis/imu）。规划对此只字未提。

**要求 Codex 明确**：

1. 把「启用 USART1 的 CubeMX 变更」列为 S3-02 的**前置架构变更项**；
2. 按阶段 2 老规矩：**由反重力指导人类用户在 CubeMX 手动操作**（出步骤、用户动手），**任何模型不得直接改 `.ioc`**；
3. 教学必须包含「重生成后逐个检查/重新 Add 那 7 个 .c 并编译验证」；
4. 明确 USART1 参数：PA9=TX / PA10=RX、115200 或 9600（随 M2 定）、8N1、无流控。

## 三、建议改（4 项）

### S1 — T3「纯编码器 360° ≤5°」不现实，指标要分模式

S2-03 已实测证明：纯编码器原地转打滑约 2 倍（0.20 m 发 90° 实转 45°）。即使用固化后的等效轮距 0.3703 f，纯编码器模式受地面/打滑影响，**很难稳定做到 ≤5°**。

**建议**：T3 验收指标**按模式分开**——

```text
IMU 融合模式：目标 ≤5°、门槛 ≤10°（硬指标）
纯编码器模式：只记录误差，不作硬通过线（物理限制，允许打滑偏差）
```

否则会把"已知物理限制"误判为失败。

### S2 — T4 回起点 ≤5 cm 难度高，建议改成分级

无外部定位、纯开环走一圈回起点，在 skid-steer 打滑下 5 cm 很苛刻（S2-03 直行 2 m 已有 ~3% 误差累积）。

**建议**：记录实测误差，把 **≤5 cm 列为争取目标**，设一个更现实的门槛（如 ≤10 cm）作为通过线；或明确允许用航向闭环辅助回环。不要让它卡住阶段 3 收官。

### S3 — S3-03 电脑端工具要定技术栈

规划只写「电脑端最小串口工具和遥测显示」。**建议明确 Python + pyserial**（Windows 最容易部署），最小功能：

```text
发 CMD_VEL(vx/omega) / CMD_STOP / CMD_MODE
收 TELEMETRY 并显示四轮 RPM、PWM、x/y/yaw、IMU yaw、状态
显示通信超时计数/丢帧率
```

否则实现模型可能做成过重的东西（GUI/上位机框架）。

### S4 — 校验类型没定死

规划写「校验」但没指定算法。**建议明确 CRC8**（基础通信用，CRC16 留阶段 4），并连同**定长帧具体字节布局**在 S3-01 里写死：

```text
帧头 | 消息类型 | 序号 | 数据(定长) | CRC8 | 帧尾
```

序号回绕、丢帧检测、重复帧处理也要在 S3-01 定清，别让实现模型各自发挥。
