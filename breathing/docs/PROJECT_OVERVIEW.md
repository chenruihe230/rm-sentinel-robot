## 2. 总体架构

```text
摄像头 / 激光雷达
        ↓
Raspberry Pi 5
  视觉检测、追踪、SLAM、导航、任务决策
        ↓
UART / USB / CAN
        ↓
STM32F407
  四轮 PID、底盘运动学、云台、发射、安全
        ↓
电机 / 编码器 / IMU / 发射机构
```

职责边界：

- 树莓派负责感知和任务决策。
- STM32 负责实时控制和安全。
- 树莓派发送高层目标，不直接操作电机 PWM。
- 无线透传用于调试、遥测和人工接管，不进入 1 ms PID 控制链路。
- 当前底盘是普通轮子四轮独立驱动差速底盘（skid-steer），无独立侧移。

## 3. 当前硬件映射

| 电机 | PWM | IN1 | IN2 | 编码器 |
|---|---|---|---|---|
| M1 | PE9 / TIM1_CH1 | PE0 | PE1 | TIM3 / PA6 / PA7 |
| M2 | PE11 / TIM1_CH2 | PE2 | PE3 | TIM4 / PD12 / PD13 |
| M3 | PE13 / TIM1_CH3 | PE4 | PE5 | TIM5 / PA0 / PA1 |
| M4 | PE14 / TIM1_CH4 | PE6 | PE7 | TIM2 / PA5 / PB3 |

其他资源：

```text
PB6 / PB7：I2C1 OLED
PA13 / PA14：SWD
PH0 / PH1：HSE 引脚
M4_IN2 = PE7（当前正式映射）
轮径 = 66.404 mm
WHEEL_DIAMETER_M = 0.066404f
```

方向逻辑：

```text
IN1=1, IN2=0 → 正转
IN1=0, IN2=1 → 反转
IN1=0, IN2=0 → 停止
IN1=1, IN2=1 → 刹车
```

## 4. 系统时序

```text
底盘 PID / 编码器采样：1 ms（方案 A，已落地）
速度低通：LPF 0.20
零计数保护：20 ms
云台 PID：1～5 ms
安全状态检查：1～10 ms
状态遥测：20～50 Hz
OLED 刷新 / 诊断窗口：100 ms（不参与 PID）
```

PID、编码器和 PWM 不依赖无线通信实现实时闭环。100 ms 只作为诊断和显示窗口，不替代 1 ms 控制周期。

## 7. 协作规则

1. 同一个文件同一时间只能有一个模型修改。
2. 免费工具优先完成调研、文档、测试和初审。
3. 付费模型只做关键架构、疑难排错和阶段验收。
4. 每个开发任务必须限定修改文件范围。
5. CubeMX、定时器、引脚和安全逻辑不得由实现模型随意修改。
6. 每个阶段完成后必须编译、测试、记录，再进入下一阶段。
7. 实车测试结果由人类确认，不以模型推测替代硬件结果。

## 10. 排错路由

```text
编译错误 → Argon4 / DeepSeek
CubeMX、引脚、定时器 → Codex
PID 震荡 → Codex 定位，Argon4 修改
编码器和里程计 → Codex 验证，Argon4 实现

视觉、雷达、ROS → Chat/Gemini 调研，Argon4 实现
接线、电源、电机、驱动器 → 人类测量，Codex 提供步骤
发射安全 → Codex 主导，硬件测试确认
```

## 11. 安全底线

```text
硬件急停优先级最高
上电默认停车
通信超时必须停车
PWM 和积分必须限幅
PID 循环禁止 HAL_Delay
发射必须有独立互锁
目标丢失必须禁止发射
```
